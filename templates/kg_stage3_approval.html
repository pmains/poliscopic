What will change, in plain English

The knowledge graph will record, for each still-unprocessed document, a processing receipt: a signed statement that this exact text version was run through the current extractor. Nothing about the documents themselves changes.

{{ counts.writes }} new receipts would be appended, in {{ counts.batches }} batches of at most {{ counts.batch_size }} rows each, starting strictly after position {{ counts.cursor }} of the plan.

Why it is needed

Today we cannot prove which text has actually been processed. Stage 3 cannot be declared complete until every eligible text version carries this proof, so the receipts are what turn "we think it ran" into something checkable.

What will not change

  • No document text, and no swept_at timestamp.
  • The {{ counts.existing_replay }} receipts already stored: they sit inside the consumed prefix, which is before the cursor. They were classified as replay no-ops, and this run starts after them, so it does not iterate, re-process, or rewrite them.
  • Nothing outside the receipt table, and nothing in production.

If something fails

The run stops at the first failure instead of pressing on, so a partial run cannot quietly become a wrong one. Every receipt is keyed to an exact text version, so re-running is idempotent: recorded work is recognised rather than duplicated. The {{ counts.existing_replay }} receipts already stored are evidence for that — each was classified as a replay no-op, and the cursor places this run after them rather than over them.

Held rows are never written. {{ counts.held_after_cursor }} rows after the cursor are held (not eligible to be written), and the consumed prefix before the cursor contains a further {{ counts.held_in_consumed_prefix }} held rows. Held means held — a held row cannot be turned into a receipt by this run.
